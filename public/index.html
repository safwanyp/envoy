How it works

Git merges text, so when two agents edit the same code someone has to fix the conflict by hand. Envoy treats each change as an intent plus a diff. It keeps agents out of each other's way while they work, and when a landing still conflicts, it re-runs the intent instead of asking anyone to resolve markers.

  1. Claim

    Before editing, each agent claims the files and functions it plans to touch. The Radar shows every claim and who holds it.

  2. Yield or proceed

    If another agent already claimed the same function, the newcomer waits for it to land. Edits to different functions in the same file go ahead.

  3. Land

    Landings run one at a time. Each agent commit carries Envoy-Intent trailers and an intent file under .envoy/intents/, so the history says why, not only what.

  4. Replay

    When main changes code an in-flight agent claimed, or a merge conflicts, Envoy drops the stale diff and runs the same intent again on current main. The new attempt is told what landed and why. After two replays the task is flagged for a human.

Stack

Cloudflare Workers
Serves this page and the /api routes.
Durable Objects
One Coordinator per project keeps claims, attempts, and landing order in SQLite, and pushes every change to this page over WebSockets.
Artifacts
Hosts the Git repos, with one main repo and one fork per agent attempt.
Queues
Delivers the main repo's push events to the Worker, which checks open claims and starts early replays.
Workers AI
Llama 3.3 70B writes the agents' edits, with scripted edits as a fallback.
isomorphic-git
Clones, commits, merges, and pushes in memory inside the Worker.
Frontend
Plain JavaScript and CSS with no framework, built with the cf CLI and Vite.
